# Local task closeout

The repository provides a small read-only acceptance check for declared local
task scope. It does not clean anything, inspect credential stores, stop native
executions or provide an OS security boundary. Remote CI cannot prove local
writer cessation.

## Records and scope

Material work uses its project's single task record, with optional evidence and
scratch beside it. Keep authority, acceptance, checkpoint, blockers, result and
closeout together. Small work can use the inline receipt form without inventing
a package. Do not use that exemption to avoid an existing package's archive.

Backlog owns outstanding priorities, state owns current authority and cross-task
constraints, decisions own durable choices, and lessons own reusable corrections.
Public behavior and tests must remain understandable without private packages.

## Read-only check

The operator's validation owner declares required acceptance invocations. The
checker accepts `--repo`, exactly one of `--task` or `--inline`, and optional
`--phase ready|closed`. Output is stdout; nonzero blocks terminal closure. There
is no apply mode. Its help text owns exact receipt keys; the sibling test file
contains a complete executable synthetic example.

A package embeds one `task-closeout:v1` marker followed by a fenced JSON receipt.
It declares Git identity, scope, preserved foreign changes, attributable writer
and consumer evidence, recovery, promotions, resources and archive references.
Evidence hashes establish identity, not the truth of native or human assertions.

The check refuses unknown ownership, dirty owned scope, unresolved Git operations,
missing evidence, active/unknown writers, unverified recovery, archive collisions
and contradictory resource dispositions. It refuses ignored untracked data in a
workspace proposed for removal. Reconcile that data first; ignored does not mean
disposable. Identified foreign files, tracked deletions and exact symlink states
can remain untouched. Never sweep foreign work to manufacture cleanliness.

## Required sequence

1. Accept the outcome and integration, or explicitly reject/supersede while
   preserving useful work. A superseded package needs a resolvable successor.
2. Reconcile actual writers and consumers through their responsible runtime or
   human. Cancellation or absence of a process CWD alone is not cessation proof.
3. Protect useful source and evidence outside disposable resources. Demonstrate
   restoration when required; a local backup is not off-host recovery.
4. Make only meaningful documentation, lesson, decision or backlog promotions.
5. Resolve owned resources through supported authorized controls. Native-managed
   workspaces keep native lifecycle controls. Never force removal.
6. Check ready prerequisites, perform authorized readable archive/reference
   disposition, then check closed readback. Pending work stays nonterminal.
7. Report actual local commits, dispositions and limits. No automatic push,
   build, deployment, credential operation or service action follows.

Retention needs a purpose, independent approving authority and review trigger.
Unknown ownership is not an exception. A trigger causes reassessment, not deletion.
The checker covers declared resources and is cooperative workflow enforcement,
not protection against a same-UID actor. Source acceptance, runtime adoption and
operational activation remain separate claims.

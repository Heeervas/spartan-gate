What does “OOM kill” mean?

An OOM kill occurs when the operating system stops a process because memory is insufficient.

Memory pressure can occur without an OOM kill. These records cover the current container lifetime.

Ten changes to consider

Open a proposal to see its change, benefit, cost, and test. The first three proposals form the first implementation group.

10 proposals

01Show the cause of memory pressureStart here+
Change
Improve the existing memory report. Correct the Hermes check that can miss memory use from other programs.
Benefit
You can distinguish a memory limit from a program stop caused by insufficient memory.
Cost
The report needs code changes. The Hermes correction can require a new image.
Test
Compare the report with container measurements. Check missing data and container restarts.
Return to the previous setup
Restore the previous report or Hermes image.

Important condition. The current Hermes check can measure one process instead of all processes in its container.

Files for implementation

scripts/memory-status.py; apps/hermes-agent/patches/; scripts/test_memory_status.py

02Start fewer tasks at the same timeStart here+
Change
Test two active sessions in one profile. Limit child tasks. Start optional tool servers only when necessary.
Benefit
Fewer tasks compete for memory. Idle tool servers can stop.
Cost
Some tasks must wait or try again. A stopped tool server needs time to start.
Test
Run normal tasks. Check response time, memory use, message delivery, and the stop command.
Return to the previous setup
Restore the previous settings. Restart the selected Hermes program and check the active settings.

Important condition. These settings do not impose one limit on all profiles. Some child tasks can still run directly.

Files for implementation

private profile config.yaml files; docs/profiles.md; scripts/hermes-resource-preset.py (new)

03Use the same tasks to compare changesStart here+
Change
Create a small test set. Include a code repair, a document search, a browser task, and task cancellation.
Benefit
You can see whether a change improves results, speed, or memory use.
Cost
Real model tests consume time and model quota.
Test
Use the same test data and model settings before and after each change.
Return to the previous setup
Remove the test configuration. Keep the results for comparison.

Important condition. Use artificial test data. Do not use private messages or account sessions.

Files for implementation

evals/spartan-workbench/ (new); optional Promptfoo test runner

04Use fewer permanent Hermes programsTest next+
Change
Test two profiles under one Hermes program. Keep their messages, settings, and browser identities separate.
Benefit
Shared program code can reduce memory use.
Cost
Some profile controls can behave differently. One program failure can affect both profiles.
Test
Use two artificial profiles. Check identity separation, message delivery, and separate stop and restart operations.
Return to the previous setup
Restore separate Hermes programs and their previous start settings.

Important condition. Hermes already has a migration function. Do not enable it directly on the existing profiles.

Files for implementation

operator migration helper (new); docs/profiles.md; existing profile and permission tests

05Add a record of task stepsTest next+
Change
Connect the existing Hermes Langfuse plugin to another computer or a hosted service.
Benefit
You can see slow tools, repeated calls, and failed task steps.
Cost
The service needs storage and maintenance. Hosted operation can have a charge.
Test
Inspect an artificial task record. Disconnect Langfuse and make sure that Hermes continues to work.
Return to the previous setup
Disable the plugin. Apply the chosen deletion policy to records already sent.

Important condition. Use metadata mode first. Exclude message content and tool values. Check the identifiers that remain.

Files for implementation

private plugin settings; dependency configuration; docs/operations.md

06Run heavy tasks in a separate workerOnly if needed+
Change
Give heavy code tasks a separate worker with its own memory limit. Test OpenSandbox for worker control.
Benefit
A task that exceeds its limit should stop without stopping Hermes.
Cost
The worker needs memory and extra control code. A worker on this laptop does not add physical memory.
Test
Exceed the worker limit in a controlled test. Check that Hermes still answers and can stop the task.
Return to the previous setup
Restore the previous execution method. Stop only the test workers.

Important condition. Keep one worker for the complete task. Preserve files between commands. Exclude browser logins and provider secrets.

Files for implementation

infra/hermes-plugins/spartan-worker/ (new); scripts/spartan-job-broker.py (new)

07Keep unrelated functions available during a failureTest next+
Change
Permit Hermes to start when optional search or page-reading services are unavailable.
Benefit
You can still use functions that do not need the failed service.
Cost
The status report must show which functions are unavailable.
Test
Stop a test search service. Check a code task and the stop command. Then restore search.
Return to the previous setup
Restore the previous start conditions and health check.

Important condition. Keep mandatory security checks. Do not select another browser automatically when Camofox fails.

Files for implementation

infra/compose/compose.yml; scripts/aliases.sh; docs/operations.md

08Test a replacement for Spartan RouteOnly if needed+
Change
Compare CLIProxyAPI or LiteLLM with Spartan Route in a separate test setup.
Benefit
An external project could maintain more provider connection code.
Cost
A replacement might lose our quota rules, account selection, or session recovery behavior.
Test
Check account access, interrupted responses, retries, session separation, and quota records.
Return to the previous setup
Keep production requests on Spartan Route until the replacement passes the required tests.

Important condition. Langfuse records task activity. Langfuse does not replace model routing or provider credentials.

Files for implementation

scripts/router-compat/ (new); existing infra/spartan-route/ tests

09Remove browser code that no task needsOnly if needed+
Change
Make Camofox the supported browser. Remove Browserless connections after checking every dependent task.
Benefit
Fewer browser connections and local code changes need maintenance.
Cost
Some meeting or Chrome-specific functions can need a replacement.
Test
Check each browser task before removal. Preserve browser account data.
Return to the previous setup
Restore the previous code and configuration for the affected connection.

Important condition. Browserless was not running during the measurement. Its removal will not release memory from an inactive service.

Files for implementation

apps/hermes-agent/ browser adapters; infra/compose/; docs/patches.md

10Make tool and network choices easier to understandOnly if needed+
Change
Add a network explanation command. Give each task only the tool descriptions that the task needs.
Benefit
You can see why a connection fails. The model receives less unrelated tool information.
Cost
A smaller tool set can omit a required function.
Test
Check allowed and blocked connections. Repeat the document-search task with the smaller tool set.
Return to the previous setup
Restore the previous tool list. Remove the new explanation command if it is not useful.

Important condition. Temporary domain access already exists. Broader public internet access needs a separate decision and network tests.

Files for implementation

scripts/whitelist-domain.sh; proposed sg-egress explain; private tool settings

04 /

Three paths

A

Improve the current setup

Keep the current services. Reduce simultaneous work and improve memory checks.

RECOMMENDED FIRSTSmallest change. Some tasks can take longer to start.
B

Separate heavy work

Give heavy code tasks a worker with its own limit. Keep Hermes available for messages.

USE IF PATH A IS INSUFFICIENTMore control code and maintenance. The laptop still has the same total memory.
C

Use another computer

Move selected workers or Langfuse away from the laptop.

USE IF CAPACITY IS INSUFFICIENTAnother computer, possible service charges, and a connection dependency.

Paths B and C can be combined. There is no need to apply every proposal.

05 /

Keep useful protection

Keep these controls

  • Separate account secrets from general task code.
  • Restrict access to the host and private network.
  • Keep browser identities separate.
  • Keep memory limits and a working stop command.
  • Keep file recovery and previous configurations.

Reduce unnecessary work

  • Start specialist programs only when necessary.
  • Reduce repeated approvals for reversible workspace changes.
  • Remove code that no required task uses.
  • Let one assistant complete simple tasks.
  • Add another service only for a clear benefit.

Trust in Hermes does not prevent a software defect or excessive memory use.

06 /

The first implementation group

  1. Restore the required free disk space through a separate cleanup task.
  2. Improve the memory report.
  3. Record the result of the test tasks with current settings.
  4. Apply task limits to one selected profile.
  5. Restart that profile and check the active settings.
  6. Repeat the same test tasks.
  7. Keep the change only if useful task results remain correct.
Stop and compare.

If these changes solve the problem, a new worker service is not necessary.

Keep at least 5 GB of disk space free. A Hermes build requires more than 10 GB free.

07 /

Terms used in this guide

Hermes
The assistant program that receives requests and uses tools.
Profile
A set of assistant settings, message connections, and session data.
Session
One conversation and its related task state.
Process
One running program instance.
Container
An environment with separate program settings and resource limits. Containers still share computer resources.
Worker
A separate program environment that performs an assigned task.
Tool server
A program that gives Hermes access to a tool. MCP is one protocol for this connection.
Plugin
An extension that adds a function to Hermes.
Memory
Temporary storage that running programs use. Memory is different from disk space.
GiB
A unit that measures memory capacity.
Metadata
Information about a task, such as its duration or tool name. Metadata can still contain sensitive identifiers.
Router
A service that sends model requests to the selected provider. Spartan Route is the current router.
Image
A packaged version of a program and its dependencies.

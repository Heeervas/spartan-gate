# Brain MCP through MCPHub — 11 November 2026

Status: **applied change** (hub-only). Hermes itself is unchanged and keeps its
native vault mount and `node_search` plugin.

## What exists now

- The `agents` MCPHub group (Claude Code and Pi) has two new stdio backends:
  - `brain-vault`: obsidian-mcp 5.0.0 (BM25 search, regex/metadata search,
    wikilinks, read, create, insert, patch, frontmatter, move, periodic notes).
    `note_delete`, whole-note `note_write`, `open_in_obsidian` and semantic
    search are disabled.
  - `brain-search`: the same `node_search` contract Hermes uses, rooted so
    result paths match Hermes (`obsidian-vault/...`).
- Inside the hub, the vault's `.git` and `.obsidian` are hidden (read-only
  empty mounts), the scripts folder is read-only and the backend's own config
  folder is read-only. Reason: an isolated test showed the backend could write
  `.git/config` and plugin code, which leads to host code execution.
- Each grant is an exact per-tool allow rule; the closed sentinel remains.
- `brain-vault` runs in local semantic mode. Its default mode downloaded an
  optional semantic-search daemon from the upstream release page and tried to
  run it (it failed on a C library mismatch); local mode skips that, and the
  downloaded binary was deleted. Semantic search stays off.
- The hub no longer passes its admin password to backends: the entrypoint
  exports it only on a first boot with no users, and the explicit copies in six
  legacy backend configurations were removed (applied the same day).

## Operating notes for Hermes

- Since 12 November 2026 every Hermes profile except the synthetic SSR consumer
  also gets both backends through its own per-profile hub group (exact per-tool
  grants, closed sentinel kept), next to the native vault mount and plugin.
  Re-running the browser-profile helper for those groups will report
  `owned_group_drift` because of the two extra entries; reconcile them instead
  of removing them.
- If an agent edits Brain notes through MCP, the change appears in the shared
  vault but is **not committed** by the MCP. Hermes jobs that find foreign uncommitted vault changes follow the
  obsidian-vault Git rule: snapshot-commit them separately before editing the
  same note, or stop if they look half-written.
- Frontmatter edits made through `brain-vault` re-serialize the whole YAML
  block (same data, different formatting). Do not treat that as corruption.

## Pending recommendations

- Install git-lfs on the host so vault pushes do not need to bypass the LFS
  hooks.
- Optional: enable the Obsidian Git plugin's auto-commit on the desktop so human
  edits are always recoverable before agents patch the same notes.

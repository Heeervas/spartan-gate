# MCPHub runtime activation — applied, 31 October 2026

Applied locally: trusted native stdio runtime closures and narrowly selected
private bindings are installed in the existing constrained hub. Selected native
clients receive explicit tool selections and execution policies; the closed
sentinel and write/publish/trading restrictions remain. Other contexts were not
merged or granted automatically.

Protocol readiness, client discovery and restart persistence were checked
separately from account/application usability. Expired account sessions require
operator login; a desktop adapter requires its application/addon, and an admitted
provider endpoint can still be unavailable. Credential-file presence and a
successful MCP envelope alone do not prove authenticated access.

Only the hub's private resource limits were adjusted from measured combined use.
No new persistent backend services, broad legacy mounts, network-policy expansion,
OAuth consent, paid inference or unrelated service recreation was performed.
The private operator guide owns current connector-specific results and recovery.

This is an operator archive note, not runtime-guide publication. Do not mount the
archive into Hermes or infer that account/application prerequisites are resolved.

# Hermes instruction consolidation and skill selection

Status: applied and verified on the operator deployment. No publication implied.

Common execution and skill-selection rules live in MASTER. The root AGENTS entry
routes to the actual profile contract; default-only operational procedures have
task-specific read routes. Personas retain role, judgment and explicit contract
bootstrap. Shared-method entry permits reuse only of complete, current reads
still available in context; adapters and required supports remain mandatory.

The native image supports `skills.selection_policy: required` for selected
profiles. Explicit requests, profile/project obligations and concrete task needs
select skills. Partial topic overlap does not trigger a preload. Both normal
and one-shot prompts use the configured selection while catalog membership,
disables, required quality/review gates and one-shot tool restrictions persist.
This is instruction guidance, not a new permission mechanism. Quoted project
content is preserved because selection is rendered before prompt composition.

Two adversarial review rounds and an affected re-review resolved a proposed
middleware provenance defect before deployment. Source regression tests, the
mandatory native gate, an isolated built-image canary and native installed-file
readbacks passed. Hermes was rebuilt and recreated; API health passed. Other
services retained their identities. Existing session identity/history was kept.
A host root-only fixture remains outside the nonroot full-suite result.

Use docs/operations.md for the opt-in, validation and cache-refresh contract.
Retain the previous image and exact scoped backups for rollback; compare before
restoring to avoid overwriting newer changes. Stored old prompts do not prove

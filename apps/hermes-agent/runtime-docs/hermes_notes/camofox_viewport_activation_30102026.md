viewport source repair is now adopted by Hermes using the existing pinned image
and two read-only private program/guard-manifest binds. Only Hermes was recreated;
Camofox and all eleven neighboring service identities/start times were unchanged.

toolset discovery includes it. Native aggregate status recovered all six served
profiles and the four existing platform connections. An installed-code scratch
journey verified real viewport and PNG dimensions at 1440×900 and 390×844, with
mobile media queries active. Owned scratch tabs were removed; browser generation
remained unchanged. No paid inference, chat sends or browser credential exports.
The original experiment page and a model-led conversation remain untested.

A transient composite health failure was isolated to timeouts on the Route
health dependency; the native API, proxy TCP and gateway connections remained
available. Health recovered without restarting/changing Route or modifying
healthcheck policy. This is not a stable dependency-health certification.

The private deployment record owns exact program/configuration beforeimages,
readback hashes and rollback. Before a future Hermes image change/rebuild,
remove the temporary two-bind adaptation once the replacement image contains
the source patch; do not reuse an old image-pinned guard manifest blindly.

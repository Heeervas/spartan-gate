# Camofox

Camofox is an optional local browser backend for Hermes browser tools. Spartan
Gate runs it as a separate Compose service named `camofox` and keeps
Browserless as the default Chromium/CDP backend.

Use Camofox for anti-detection experiments and browser-tool tasks where a
Camoufox/Firefox-based browser is useful. Camofox also backs Google Meet
`mode=transcribe` when `CAMOFOX_URL` is set. Keep Browserless for CDP behavior,
Google Meet realtime audio, Browserless profile seeding, Chrome DevTools MCP,
and the persistent Browserless `main` profile broker.

In Camofox mode, `sg-hermes-meet setup` and `sg-hermes-meet-join` use
`CAMOFOX_USER_ID` and ignore stale `HERMES_MEET_CDP_URL` values.

## Enable

Camofox starts as an internal service, but Hermes will not use it unless
`CAMOFOX_URL` is set. `CAMOFOX_URL` is the canonical selector; when
`COMPOSE_PROFILES` is set it must match:

```env
COMPOSE_PROFILES=camofox
CAMOFOX_URL=http://camofox:9377
CAMOFOX_ACCESS_KEY=<private-key>
```

`CAMOFOX_ACCESS_KEY` is passed to the Camofox service and to Hermes. Camofox
protects most routes with `Authorization: Bearer <key>` when this key is set.
`GET /health` remains a shallow diagnostic and does not prove that Camoufox can
create a context or page. Docker readiness instead consumes the PID-1
supervisor status, which is refreshed only after a private loopback probe has
created, loaded, evaluated, and closed a raw Playwright context/page.
`CAMOFOX_API_KEY` is generated separately for dedicated cookie/storage routes.
Hermes receives the access key under upstream Hermes' `CAMOFOX_API_KEY` client
variable so upstream Camofox auth headers work without a local Hermes patch.

## Runtime State

Camofox state is separate from Browserless state.

- Public default: `runtime/camofox/`
- Private override: `SPARTAN_CAMOFOX_DATA_PATH`
- Container path: `/root/.camofox`

Camofox persistence stores Playwright `storageState` under
`CAMOFOX_PROFILE_DIR`, keyed by Camofox/Hermes user IDs. It is not a Chromium
`--user-data-dir` and is not compatible with `runtime/browserless/profiles`.

For manual login profiles, use stable IDs generated by the helpers:

```text
main -> spartan-camofox-main
alt  -> spartan-camofox-alt
```

`sg-camofox-profile-save` only verifies/checkpoints state. It does not delete a
Camofox session, because deletion can remove persisted browser state.

To reset one helper-managed Camofox profile:

```sh
source scripts/aliases.sh
sg-camofox-profile-reset main
```

For a full manual wipe, stop `hermes` and `camofox`, then remove the directory
configured by `SPARTAN_CAMOFOX_DATA_PATH` or the public `runtime/camofox/`
directory.

## Automatic Recovery

The wrapper runs `spartan-camofox-supervisor.py` as PID 1. It owns the Node
server process group, reaps children, and checks deep browser readiness every
20 seconds. The internal deep-health and recovery routes require both loopback
origin and an ephemeral credential stored in a mode-`0600` file under `/run`.
When the global access gate is enabled, the supervisor also supplies that
bearer only over the same proxy-disabled loopback connection. Neither
credential is passed in argv, logged, or exposed on the Compose network.

Public GET /health is passive readiness: it never launches a browser or runs a
probe in the request path. It returns 200 only while the last private deep probe
is fresh, belongs to the currently published browser generation, and the
lifecycle coordinator is not degraded or recovering. Missing, stale, or
wrong-generation proof returns 503. GET /live only proves that the Node event
loop can answer and remains independent of browser readiness.

Three consecutive terminal timeouts from real goto work in POST /tabs with a
URL or POST /tabs/:tabId/navigate latch browser_navigation_degraded for that
browser generation. Retries and cleanup settle the attempt only once; late
completions from an old generation cannot clear or contaminate its replacement.
Capacity rejection, queue/handler timeouts, validation, policy/proxy/SSL
failures, aborts, and creates without a URL do not participate. The next
supervisor poll treats the latched code as a hard browser fault and attempts
one recovery for the exact child PID and browser generation. Other deep
failures retain the normal three-sample threshold.

If in-process recovery does not publish and deeply verify a different browser
generation, the supervisor terminates the Node/Camoufox process tree and
relaunches it only after every tracked PID has disappeared.
The durable retry schedule is `0s, 30s, 2m, 10m, 30m`, capped at one attempt per
30 minutes during a sustained fault and reset only after 30 continuously
healthy minutes. If a process remains in uninterruptible `D` state, readiness
stays unhealthy and no second browser is launched; the supervisor retries
cleanup at the maximum backoff.

Local capacity exhaustion returns 429 immediately; queue timeout, navigation
timeout, degraded/recovering browser state, and other internal inability return
503. Fly admission keeps its existing replay-oriented 503 behavior. Only
allowlisted semantic fields are exposed; logs retain redacted diagnostic detail.

Each create registers a per-request token immediately after request validation
and before it waits for the global lifecycle FIFO. The registry is bounded to
one running create plus `MAX_SESSIONS` waiters and ref-counted per user. Empty
groups, session timeout, memory-pressure eviction, pressure cleanup, and the
empty-session reaper preserve a user while any queued token remains. After
admission, the existing per-session fence continues to protect the exact group
and orphan-page cleanup.

Both fences remain until the underlying create promise settles, including after
an HTTP timeout. Each token stores the request's effective absolute deadline:
30 seconds normally or the longer proxy-rotation allowance when configured.
Deep health therefore rejects a truly overdue create without killing a valid
long-running proxy retry.

Dead-context, proxy, and navigation-error teardown marks the exact session
closing, invalidates any create already bound to it, and delays context close
until that create settles. The invalidated request fails explicitly, while
compare-and-delete preserves any same-user replacement. The deprecated
`POST /tabs/open` path is disabled with HTTP 410; callers must use the fenced
`POST /tabs` route. These bounds close the admission-versus-reaper and
create-versus-destroy races without retaining unrelated garbage indefinitely.

The watchdog ledger is separate from browser credentials:

```text
/var/lib/spartan-camofox-watchdog/ledger.json
```

The ledger is bound to the supervisor revision. Recreating the same revision
keeps the accumulated backoff, while deploying a different revision grants one
immediate launch attempt and then reapplies the accumulated backoff level if
that attempt fails. This allows a fixed image to recover without deleting
diagnostic state or enabling a same-image force-recreate loop.

Do not mount `docker.sock`, add an autoheal sidecar, or use profile reset as a
recovery action. For diagnosis, preserve logs before any recreate and inspect
only allowlisted timestamps, stages, PIDs and resource counters.

After deployment, run the non-secret acceptance summary:

```sh
source scripts/aliases.sh
sg-camofox-acceptance https://example.com/
```

It executes 20 sequential lifecycles and five concurrent identities, requires
each evaluation to return `true`, closes each tab in `finally`, and requires
`activeTabs` to return to the captured baseline.

The five clients remain concurrent at the API, but create lifecycles use one
global FIFO slot. The FIFO is capped at `MAX_SESSIONS` waiters, with one
additional bounded token for the running create, and cancels a waiter before
its outer handler deadline. Registering that token before FIFO admission keeps
the minute reapers from closing an empty context underneath a queued burst.
Local evidence also showed that allowing two Camoufox context navigations at
once could stall both, so the browser mutation lane intentionally remains
single-owner.

Then exercise supervised recovery with a bounded, reversible browser-only fault:

```sh
sg-camofox-deep-health-fault-test
```

The fault test sends `SIGSTOP` only to the child `camoufox-bin`, requires
Docker health to become `unhealthy`, and waits for a different healthy browser
PID without a Docker container restart. A trap resumes the old PID if recovery
does not replace it.

Fault injection deliberately uses the same durable recovery ledger as a real
failure. Repeating it before the 30-minute healthy-reset window expires can
move the next child recycle to a later configured backoff step (`30s`, `2m`,
`10m`, then `30m`). Do not delete or reset the ledger after a test; wait for the
healthy window when measuring steady-state recovery latency.

Rollback is independent by owner:

1. Revert the supervisor/Compose commit and rebuild/recreate only Camofox while
   retaining the timed-out tab cleanup.
2. Run `sg-camofox-profile-isolate rollback`, then revert profile identity
   defaults separately; keep global adoption disabled unless one owner is guaranteed.
3. Revert the tab-lifecycle fix only if reintroducing the original timeout is
   accepted.

No rollback step deletes `/root/.camofox` or resets a profile.

## Egress

Camofox browser traffic must go through Spartan Gate's outbound policy. The
Compose service sets both generic proxy variables and Camofox's browser proxy
variables:

```env
PROXY_HOST=proxy
PROXY_PORT=8888
HTTP_PROXY=http://proxy:8888
HTTPS_PROXY=http://proxy:8888
```

If a target page fails unexpectedly, verify Tinyproxy logs before assuming the
browser is using the expected network path.

## Image

Spartan Gate builds a thin local wrapper image:

```env
CAMOFOX_BASE_IMAGE=ghcr.io/jo-inc/camofox-browser:1.11.2@sha256:826da04c4ec75b3eb450bc7cf2513176ba408f92b862b89f768ca30563171137
CAMOFOX_IMAGE=spartan-gate-camofox:1.11.2
```

The wrapper does not fork Camofox. It pre-fetches Camofox's default uBlock
Origin add-on at build time. Upstream Camofox otherwise downloads that add-on
on first browser launch with Node `fetch`, which does not follow Spartan Gate's
runtime Tinyproxy path and fails while the service is correctly isolated on
`spartan_internal`.

The wrapper also makes upstream Camofox geo-IP proxy probing opt-in through
`CAMOFOX_GEOIP`. The default is `false` because Spartan Gate's normal Camofox
proxy is local Tinyproxy, not a residential proxy with a useful geolocation
target.

## Add-ons

Camofox can load extracted Firefox add-ons through `CAMOFOX_ADDONS`. The value
is a comma-separated list of container paths. For private add-ons, keep the
files on the host and bind them into the container read-only.

The private Obsidian Web Clipper install uses this mapping:

```text
Host:      SPARTAN_CAMOFOX_DATA_PATH/addons/web-clipper-obsidian
Container: /opt/camofox-addons/web-clipper-obsidian
Env:       CAMOFOX_ADDONS=/opt/camofox-addons/web-clipper-obsidian
```

Set `SPARTAN_CAMOFOX_ADDONS_PATH` to the host `addons` directory. The private
Compose example mounts it read-only at `/opt/camofox-addons`.

The mounted directory must be an extracted add-on with `manifest.json` at its
root; raw `.xpi` files are not passed to Camofox directly.

### Headless Obsidian Clipping

When the Obsidian Web Clipper add-on is configured, the Camofox wrapper stages a
temporary copy and appends a small bridge to the staged `content.js`. The
private mounted add-on is not modified.

Agents must not use noVNC/VNC for clipping. Use the authenticated Camofox API:

```http
POST /tabs/{tabId}/extensions/obsidian-web-clipper/clip
Authorization: Bearer <CAMOFOX_ACCESS_KEY>
Content-Type: application/json

{
  "userId": "spartan-camofox-main",
  "mode": "saveFile",
  "waitForDownloadMs": 10000,
  "includeData": true
}
```

The route verifies that `tabId` belongs to `userId`, triggers the extension's
existing `saveMarkdownToFile` handler through a one-shot bridge token, and
returns the single new download captured for that tab. Bridge invocation and
download capture run under Camofox's per-tab lock so navigation, close, and
concurrent clip operations cannot race the request.

## Runtime Viewport

Spartan Gate adds an authenticated runtime viewport route for tabs created by
Camofox. Use it when Hermes or an operator needs responsive CSS to see a mobile
viewport, not just a narrow screenshot crop:

```http
POST /tabs/{tabId}/spartan/viewport
Authorization: Bearer <CAMOFOX_ACCESS_KEY>
Content-Type: application/json

{
  "userId": "spartan-camofox-main",
  "width": 390,
  "height": 844,
  "reload": false,
  "relaunch": true
}
```

The Spartan route verifies tab ownership, runs under Camofox's per-tab lock,
and first tries Playwright `page.setViewportSize`. Firefox/Camoufox does not
always apply that live resize to the runtime viewport. When `relaunch: true` is
present, Spartan Gate restarts the shared Camofox browser with Camoufox's
launch-time `window` option sized so the page runtime sees the requested inner
viewport, then recreates the same `tabId` and reopens the current HTTP/HTTPS
URL. `/tabs/{tabId}/viewport` is also routed through this verified Spartan
handler. The original upstream handler is displaced to a fail-closed `410
upstream_viewport_disabled` route because it only returned requested
width/height without proving effective runtime dimensions. If
`window.innerWidth` or `window.innerHeight` still does not match, the route fails
with `viewport_mismatch` instead of returning a misleading `ok`.

Launch-window relaunch is a shared browser operation and closes other active
Camofox sessions/tabs. Omit `relaunch` to keep the route non-destructive; it
will fail closed with a hint when live resize does not take effect. Use scratch
sessions for diagnostics.

Live `deviceScaleFactor`, `isMobile`, touch, and `userAgent` changes are not
claimed. Requests containing those fields fail with
`unsupported_viewport_options` until Camofox supports them safely.

Hermes-path diagnostic:

```sh
source scripts/aliases.sh
sg-camofox-viewport-check 390 844
```

The diagnostic runs inside the `hermes` container against
`http://camofox:9377`, creates a scratch `spartan-viewport-smoke-*` session,
checks viewport-before-navigation, viewport-after-navigation, viewport-then-
reload, and create-with-viewport observation, captures `fullPage=false`
screenshot dimensions, verifies the screenshot is non-empty and dimensionally
matches the effective viewport, records viewport strategy and before/effective
dimensions, and deletes the scratch session.

## noVNC

The Camofox VNC plugin is disabled by default:

```env
CAMOFOX_ENABLE_VNC=0
```

If you need human browser interaction, enable it only in private env. The
private Compose override exposes noVNC through Caddy on
`CAMOFOX_NOVNC_PORT`, with Caddy Basic Auth and the VNC password:

```env
CAMOFOX_ENABLE_VNC=1
CAMOFOX_VNC_PASSWORD=<private-password>
CAMOFOX_NOVNC_PORT=26080
```

Do not expose Camofox's API port `9377` on the host by default.

The default Caddyfile includes the HTTP `:26080` listener used by the private
port mapping. The live-profile helper validates the rendered mapping, internal
noVNC health, and public Caddy reachability. With HTTPS, `TAILSCALE_HOST` must
resolve to `TAILSCALE_IP` and be valid for the configured certificate; there is
no raw-IP fallback.

## Manual Login Profiles

Open a Camofox profile for human login:

```sh
sg-camofox-profile-live main https://accounts.google.com
```

The helper opens the selected `userId` in the reserved
`spartan-operator-login` tab group. Hermes uses `spartan-hermes` in the same
browser context, so both groups share cookies and login state without adopting
or navigating each other's tabs. The helper creates the operator tab in
non-destructive mode: if Camofox is at capacity or navigation hits a proxy
failure, it fails instead of recycling a tab or rotating the shared browser
session. Before posting the tab, the helper checks an authenticated,
versioned capability exposed by the patched Camofox image; an older image
fails closed and must be rebuilt before the helper can be used. A failed
operator navigation also removes the newly created operator tab.

If Hermes already uses this profile, log in through the printed noVNC URL and
checkpoint it without changing Hermes configuration or recreating services:

```sh
sg-camofox-profile-save main
```

Only when selecting this profile for Hermes for the first time, and after
active browser work has finished, apply it explicitly:

```sh
sg-camofox-profile-save main
sg-camofox-profile-use main
sg-browser-mode-apply
```

The printed noVNC URL opens `vnc_lite.html` directly and includes the VNC
password from `CAMOFOX_VNC_PASSWORD` in the URL fragment. The fragment is not
sent to Caddy or websockify. If Camofox is already running and noVNC is healthy,
the helper reuses it instead of rebuilding or recreating the service.
The URL also carries a version query that bypasses older cached noVNC shells.
Caddy marks authenticated noVNC responses `no-store`, ensuring that loading the
page refreshes the edge-session cookie before the WebSocket handshake.

Hermes receives the runtime `CAMOFOX_ACCESS_KEY` needed to call Camofox, and
also receives that same protected-route token as `CAMOFOX_API_KEY` for upstream
Hermes' Camofox auth helper. It also receives `CAMOFOX_USER_ID`,
`CAMOFOX_SESSION_KEY`, and
`CAMOFOX_ADOPT_EXISTING_TAB` from the selected private env so browser tools use
the same saved Camofox profile instead of a new ephemeral `hermes_*` session.
Adoption is restricted to the exact Hermes tab group; the legacy
`manual-login` value is mapped to `spartan-hermes` at runtime. The reserved
operator group cannot be selected through `sg-camofox-profile-use`.
It does not receive the human account password, 2FA material, or personal API
keys. Use a different profile name, such as `alt`, for isolated cookies and
login state.

## Smoke Tests

Healthcheck:

```sh
sg-camofox-health
```

Protected-route browser smoke:

```sh
sg-camofox-smoke
```

The smoke helper creates a tab through Camofox with bearer auth, navigates to
`https://example.com`, lists tabs, and closes the test session. It is a better
integration check than `/health` because it exercises auth and the browser tab
lifecycle.

## Known Limits

- Camofox does not replace `BROWSER_CDP_URL` or `BROWSER_CDP_MAIN_URL`.
- Hermes `browser_cdp` functionality remains Browserless/Chromium-backed.
- Google Meet realtime audio remains Browserless CDP or explicit host Chrome
  CDP only; Camofox supports transcribe mode.
- Browserless profile seeding stays Browserless-only.
- Camofox is Firefox/Camoufox-based, so site behavior may differ from Chromium.
